# 数据库选用 SQLite（与说明书一致）

Status: Accepted
Date: 2026-09-01

## 背景
说明书 1.6 指定 QSQLite；系统结构图（AI 生成，技术栈已声明忽略）画的是 MySQL 系。团队对三个候选均无实质经验（倾向避开 MySQL）。评估项目对数据库的真实需求后做选择。

## 需求评估（结论：无数据库扩展需求）
- 写入方唯一：仅 biz-core 写库（ADR-0001），无多写者并发压力
- 数据量：演示/验收规模，30~60 天模拟历史，万行级
- 距离计算、聚合统计均在应用层完成，不需要地理扩展/物化视图/存储过程
- ML 契约是 CSV 进、预测结果写回单表，Python 端 sqlite3 为标准库，零驱动成本
- 事务需求（订单状态流转）SQLite 完整支持

## 决定
用 **SQLite**（WAL 模式），biz-core 经 Qt6 QSQLITE 驱动访问，是唯一写者；DB 文件路径进配置文件。

## Considered Options
- PostgreSQL：功能冗余（本项目用不到任何 PG 特有扩展），部署多一个服务，五人环境一致性成本高；唯一收益是"数据库服务器"观感
- MySQL：团队明确倾向避开

## 后果
- 与说明书验收口径完全一致（1.6 指定 QSQLite）
- VM 部署清单少一项数据库服务；库文件即备份
- 若未来出现多进程直读需求，靠 biz-core 暴露接口解决，不给其他进程开库连接
