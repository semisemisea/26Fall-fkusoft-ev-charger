# 常驻服务端进程作为唯一数据权威（biz-core）

## 背景
充电桩平台包含用户端(user-app)、后台管理端(ops-app)、Web大屏(dashboard)、模拟电桩(simulator)、ML(ml) 多个消费方，需要数据一致性和"预约-充电-计费-结算"状态机的中立裁判。曾考虑：a) 用户端↔后台点对点；b) 各进程直读共享 SQLite 文件。

## 决定
建一个常驻 QT 服务端进程 **biz-core**，作为唯一数据权威：
- 唯一持有数据库写权，其他进程一律不直连业务库
- TCP socket 服务：user-app / ops-app / simulator 均为客户端，长连接，协议 = 4 字节长度头 + JSON 包体，请求-响应为主，服务端可主动推送（桩状态变化、订单结算完成）
- HTTP API：dashboard 大屏经 biz-core 提供的 HTTP 快照接口取数，不触库
- 内部多线程：主线程 accept + IO 线程池 + 业务队列（命中"多线程主框架"考核点）

## 理由
- 点对点方案下后台非常驻，管理员离线即服务中断，且状态机无中立裁决方
- 共享文件直读在多进程并发写下有锁冲突，且绕开 socket 考核点
- 订单状态机、远程重启指令下发、大屏供数天然有统一落点

## 后果
- biz-core 是关键路径，协议 v1 必须最早冻结（D2）
- 所有客户端依赖协议定义（common/），协议变更需同步
