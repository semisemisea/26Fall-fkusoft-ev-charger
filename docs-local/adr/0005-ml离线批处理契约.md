# ML 子系统：离线批处理，CSV 进 / 预测表出

## 背景
五部分全部必做，ML 完整做但必须与主系统解耦（Opt-in）。周期仅 10 天，验收 9/11。

## 决定
- 形态：ml/ 独立 Python 目录（pandas + statsmodels/sklearn），不进 CMake，Qt 主工程零依赖
- 输入：biz-core 导出的历史充电记录 CSV（时间/站ID/桩ID/电量/时段），历史数据由造数脚本批量生成 30~60 天模拟记录
- 模型：按 站×小时 聚合的时序预测（Holt-Winters / 轻量 GBM 起步，不引入深度学习）
- 输出：未来 1h/6h/24h 各站负荷 + 空闲桩数，写回业务库 ml_prediction 表
- 消费方：dashboard 负荷预测曲线；user-app 站列表"低拥堵/高空闲优先"推荐排序开关；ops-app 负荷预警行
- 触发：定时重跑（默认现实每 2 分钟一次，配合加速因子≈模拟时间一天，形成准实时刷新；亦可手动触发），不在请求路径上

## 理由
- 契约（CSV in → prediction 表 out）冻结后模型可独立替换升级，符合"解耦、Opt-in"要求
- 不拖累关键路径（biz-core 协议/状态机）

## 后果
- biz-core 需提供导出工具与 ml_prediction 表 schema
- 演示前需预跑一次批处理保证大屏有预测数据
