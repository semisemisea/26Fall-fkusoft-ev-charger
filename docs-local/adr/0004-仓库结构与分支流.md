# Monorepo + 短命 feature 分支 + Rebase merge

Status: Accepted
Date: 2026-09-01

## 背景
五人协作（Agent 主写码、人验证），仓库 github.com/semisemisea/26Fall-fkusoft-ev-charger 已由组员建立初始结构。

## 决定
- Monorepo 单仓，目录：biz-core/（服务端）ops-app/（后台）user-app/（用户端）common/（协议与公共库）simulator/ dashboard/ ml/，以及不入库的 docs-local/
- 分支流：main 保护 + 短命个人分支 `feature/名字-模块`，PR 互评（对应 PRL 职责），**Rebase merge**（保留线性历史，不 squash）
- 现有分支 feature/add-clang_format 待合入 main
- 构建统一 CMake + Qt6 + C++17，.clang-format 全仓生效

## 理由
- 10 天周期需要低成本协作模型；PR+互评满足实训过程管理要求
- Rebase merge 保持线性历史便于回溯，组内已倾向此模型

## 后果
- dashboard（纯静态）/ ml（Python）不进 CMake，仅目录约定
- 仓库初始结构以组员分支为准，新增目录待该分支合入后对齐，不抢建

## Considered Options
- 多仓分拆：五人五仓并行快，但协议 common/ 同步与联调成本高，10 天周期不可承受
- trunk-based（直接提交 main）：过程管理要求 PR 互评（PRL 职责），故保留短命分支
