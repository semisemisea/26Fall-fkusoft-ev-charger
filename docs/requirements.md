# 电动汽车充电综合服务平台后端需求

## 1. 范围与约束

### 1.1 交付范围

后端提供以下能力：

- 用户免密登录、个人资料、头像和钱包管理；
- 电站定位、附近电站查询、电桩查询和路线规划；
- 电桩预约、模拟充电、计费、停止和钱包结算；
- 管理员登录、营收统计、电站管理、电桩管理和用户冻结管理；
- `USER`、`ADMIN`、`ADMIN_READONLY` 和 `SERVICE` 四类身份的认证与授权。

`SERVICE` 身份本期仅能查询自身身份。不提供机器学习、预测分析和 Web 大屏专用接口。

### 1.2 技术边界

- 后端是独立进程，使用 C++20 和 Qt 6.2.4。
- 后端通过 JSON over HTTP 提供接口，可使用兼容 Qt 6.2.4 的第三方 HTTP Server 库。
- 业务数据只保存在一个 SQLite 数据库中。只有后端进程可以访问该数据库。
- Qt 用户端和管理端只能通过 HTTP 调用后端，不能直接访问 SQLite。
- 后端可单机运行，也可配置为在局域网地址上监听。
- 后端直接提供 HTTP。HTTPS 由部署环境中的反向代理终止。
- 后端使用多线程处理请求。每个工作线程使用独立的 SQLite 连接。

## 2. 通用数据约定

### 2.1 标识符

用户、管理员、电站、电桩、预约、订单和钱包流水均使用 SQLite 生成的全局唯一正整数 ID。已分配的 ID 不得复用。

电桩 ID 同时作为面向客户端显示的电桩编号。电桩另行保存所属电站 ID，不设置独立电桩编号字段。订单不设置独立订单号。

### 2.2 时间

- 时间戳采用 RFC 3339/ISO 8601。
- 数据库按 UTC 保存时间，响应统一使用 `Z` 后缀。
- 请求中的时间必须包含 `Z` 或明确的 UTC 偏移。
- 时间区间采用半开区间 `[from, to)`，且必须满足 `from < to`。
- 需要时间区间的接口中，`from` 和 `to` 必须同时提供或同时省略。
- 生产环境使用系统 UTC 时钟。业务核心通过可替换的时钟依赖读取时间，测试可使用固定时钟。

### 2.3 金额、功率和电量

- 金额使用有符号 64 位整数，单位为分。
- 电站单价使用整数分/kWh，必须为正数，不得超过配置上限；默认上限为 1,000,000 分/kWh。
- 电桩功率的接口单位为 kW，必须为正数，最多三位小数，不得超过配置上限；默认上限为 1000 kW。
- 功率进入业务核心后精确转换为整数 W。
- 充电原始电量使用整数 Ws 表示，不使用二进制浮点数参与计费。
- 对外返回的 kWh 四舍五入到小数点后两位，0.005 kWh 进位。
- 金额舍入采用半分进位。
- 任何整数运算发生溢出时，操作失败且不得改变业务状态。

## 3. 配置

### 3.1 加载规则

- 默认配置文件为可执行文件同目录的 UTF-8 `config.ini`。
- 配置优先级依次为环境变量、INI 文件、内置默认值。
- 配置仅在进程启动时加载一次。
- 已配置但格式错误或超出合法范围的值会导致启动失败，不得静默回退。
- 腾讯地图密钥和 SERVICE 令牌只能通过环境变量提供。

## 4. 领域模型

### 4.1 状态

| 资源 | 状态 |
| --- | --- |
| 用户 | `active`、`frozen` |
| 管理员 | `active`、`disabled` |
| 电站 | `active`、`inactive` |
| 电桩占用状态 | `available`、`reserved`、`charging` |
| 电桩运维状态 | `online`、`fault`、`offline` |
| 预约 | `active`、`used`、`cancelled`、`expired` |
| 订单 | `charging`、`awaiting_payment`、`settled` |
| 钱包流水类型 | `top_up`、`charge_debit` |

电桩占用状态和运维状态是两个独立维度。只有占用状态为 `available` 且运维状态为 `online` 的电桩可以接受预约或直接开始充电。

### 4.2 软删除

- 电站和电桩使用独立的 `deletedAt` 表示软删除。
- 软删除资源不参与普通查询、附近查询、可用数量、状态计数或新业务。
- 管理员列表默认排除软删除资源，指定 `includeDeleted=true` 时包含。
- 不提供恢复接口。
- 软删除不改变历史预约、订单、钱包流水或营收。
- 用户和管理员不提供删除功能。

## 5. 认证与授权

### 5.1 用户登录

- 手机号必须恰好由 11 个 ASCII 数字组成，不校验运营商号段。
- 手机号不存在时创建 `active` 用户，余额为 0，昵称为“用户”加手机号后四位。
- 手机号具有数据库唯一约束。并发首次登录只能创建一个用户，所有成功请求分别获得令牌。
- `active` 用户可直接登录。
- `frozen` 用户存在 `charging` 或 `awaiting_payment` 订单时可以登录并获得受限令牌；不存在未完成订单时登录返回 `USER_FROZEN`。

### 5.2 管理员登录

- 首次初始化数据库时创建用户名 `admin`、密码 `123456`、角色 `ADMIN` 的管理员。
- 密码使用带随机盐的密码哈希保存，不保存明文。
- 账号不存在和密码错误统一返回 `INVALID_CREDENTIALS`。
- `disabled` 管理员不能登录，返回 `FORBIDDEN`。
- 本期不提供管理员账号新增、删除、角色修改、密码修改或重置接口。
- 默认数据库不创建 `ADMIN_READONLY` 账号，但后端实现该角色的授权规则。

### 5.3 令牌

- 用户和管理员令牌由密码学安全随机源生成 32 字节，并以 Base64URL 编码返回。
- 数据库只保存令牌的 SHA-256 哈希、主体、角色、创建时间、到期时间和撤销时间。
- 用户和管理员令牌有效期为 7 天。同一账号可以同时存在多个有效令牌。
- 退出登录只撤销当前令牌。
- 缺少、无效、过期或已撤销令牌统一返回 `UNAUTHORIZED`。
- 身份有效但权限不足时返回 `FORBIDDEN`。

### 5.4 SERVICE 身份

- 环境变量提供 SERVICE 固定令牌时，启动过程保存其哈希，并建立 `serviceName=ml`、角色为 `SERVICE` 的主体。
- 未提供 SERVICE 令牌时，服务正常启动，但不存在可用的 SERVICE 身份。
- SERVICE 只能调用当前身份查询接口，不支持退出接口。

### 5.5 权限

| 角色 | 权限 |
| --- | --- |
| `USER` | 本人资料、头像、钱包、预约和订单；公开位置与电站查询 |
| `ADMIN` | 营收与设备统计、订单查询、用户管理、电站和电桩管理 |
| `ADMIN_READONLY` | 营收与设备统计、电站和电桩只读查询 |
| `SERVICE` | 查询自身身份 |

冻结用户可以读取本人资料、预约历史、订单和钱包流水，可以停止当前充电、充值、结算和退出登录。其他用户写操作返回 `USER_FROZEN`。

普通用户访问不存在的订单和访问他人的订单均返回 `NOT_FOUND`。

## 6. 用户资料、头像与钱包

### 6.1 资料

- 用户可以查看本人资料和修改昵称，不能修改手机号。
- 昵称去除首尾空白后必须为 1 至 30 个 Unicode 字符，允许重名。

### 6.2 头像

- 头像请求中声明的 MIME 只能是 `image/jpeg` 或 `image/png`。
- 后端只校验声明的 MIME 和正文大小，不解码或检查图片内容。
- 后端将原始字节和声明的 MIME 直接保存在 SQLite BLOB 中。
- 上传新头像在一个事务中替换旧头像。
- 删除头像会清除 BLOB 和 MIME；重复删除仍成功。
- 用户资料只返回是否存在自定义头像。头像内容由独立接口返回。

### 6.3 钱包

- 充值金额必须是整数分，并处于配置的单次充值范围内。
- 充值后的余额不得超过配置的余额上限。
- 充值为同步模拟成功，不接入支付服务。
- 每次充值写入一条不可变的 `top_up` 流水并更新余额。
- 订单结算写入一条不可变的 `charge_debit` 流水并扣减余额。
- 余额不足时不部分扣款，订单保持 `awaiting_payment`。
- 0 分订单结算时仍写入金额为 0 的 `charge_debit` 流水。
- 不提供退款、管理员调账、透支、流水修改或流水删除。

## 7. 电站、位置与路线

### 7.1 电站

- 创建电站时不创建电桩，初始状态为 `active`。
- 电站名称去除首尾空白后为 1 至 100 个 Unicode 字符。
- 纬度范围为 `[-90, 90]`，经度范围为 `[-180, 180]`。
- 管理端新增电站时可通过腾讯地图选点填写经纬度；地图不可用时保留手工输入。
- 名称不要求唯一，电站以 ID 唯一标识。
- 管理员可修改名称、经纬度、单价和 `active/inactive` 状态。
- 预约不锁定电站单价；订单开始时才保存单价快照。价格修改只影响修改后开始的订单。
- 电站重新启用时，站内电桩保持各自已有状态。

电站变为 `inactive` 时，在同一事务中将站内全部有效预约标为 `expired` 并解除对应电桩占用。正在充电和待结算订单不受影响。`inactive` 电站不能接受新预约或新订单。

### 7.2 电桩

- 管理员向未软删除电站逐个新增电桩。
- 新电桩必须指定 `fast` 或 `slow` 类型以及功率。
- 新电桩初始占用状态为 `available`，运维状态为 `online`。
- 电桩所属电站创建后不可修改。
- 管理员可修改类型、功率和运维状态，不能直接修改占用状态。
- 类型只用于分类；模拟充电按功率计算。
- 修改功率只影响修改后开始的订单。

已预约电桩变为 `fault` 或 `offline` 时，在同一事务中将预约标为 `expired` 并解除占用。正在充电的电桩可以变为 `fault` 或 `offline`，订单继续充电；停止后占用状态恢复为 `available`，运维状态保持不变。

远程重启只允许占用状态为 `available` 且运维状态为 `fault` 或 `offline` 的电桩。重启同步将运维状态改为 `online`，不保存重启记录。重复设置已有运维状态时幂等成功。

### 7.3 软删除操作

- 电桩存在有效预约或正在充电订单时，拒绝软删除。
- 电站内任一电桩存在有效预约或正在充电订单时，拒绝软删除电站。
- 待结算订单不阻止软删除。
- 软删除电站时，在同一事务中软删除其全部未删除电桩。
- 重复软删除幂等成功。

### 7.4 附近电站

- 调用方必须提供完整经纬度，或提供地址及可选区域；两种位置输入同时出现时返回校验错误。
- 调用方必须提供大于 0 且不超过配置上限的查询半径。
- 附近查询只返回未软删除、状态为 `active`、距离不超过半径的电站。
- 可用电桩数只统计未软删除、占用状态为 `available` 且运维状态为 `online` 的电桩。
- 距离使用 Haversine 大圆距离，地球半径固定为 6371.0088 km。
- 排序使用未舍入距离，返回距离四舍五入到小数点后两位。
- 距离排序按距离升序、电站 ID 升序。
- 价格排序按单价升序、距离升序、电站 ID 升序。

### 7.5 腾讯地图

- 地址解析和路线规划由后端调用腾讯地图服务。
- 地址去除首尾空白后为 1 至 200 个字符；可选区域为 1 至 100 个字符。
- 路线规划只支持 `driving` 和 `walking`。
- 路线结果包含方式、距离米数、预计秒数、路线折线和可加载的腾讯地图 URL，不持久化查询结果。
- 地图密钥缺失时，地址解析和路线规划返回 `SERVICE_UNAVAILABLE`；使用经纬度的附近查询不受影响。
- 连接失败、超时和 HTTP 5xx 按配置次数重试；参数错误、鉴权失败和无结果不重试。
- 地址无结果返回 `GEOCODE_FAILED`，路线无结果返回 `ROUTE_NOT_FOUND`，最终网络失败或 5xx 返回 `SERVICE_UNAVAILABLE`，供应商鉴权失败或异常响应返回 `PROVIDER_ERROR`。

## 8. 预约

### 8.1 创建

- 预约从后端接收请求的时刻开始生效。
- 请求必须提供整数分钟 `holdMinutes`，范围为 1 至配置的最大预约时长。
- 创建时保存 `createdAt` 和确定的 `expiresAt`，不保存独立未来开始时间。
- 用户必须为 `active`，不得已有有效预约，不得已有 `charging` 或 `awaiting_payment` 订单。
- 电站必须 active 且未软删除；电桩必须未软删除并处于 `available + online`。
- 创建预约和把电桩置为 `reserved` 必须在同一事务中完成。
- 并发预约同一电桩时只能有一个请求成功，其他请求返回 `CHARGER_UNAVAILABLE`。

### 8.2 使用、取消和过期

- 预约仅在 `createdAt <= 当前时间 < expiresAt` 时有效。
- 有效预约只能由其所属用户用于启动该电桩。
- 开始充电后，预约变为 `used`，订单保存预约 ID；该预约不能再次使用或取消。
- 用户可取消尚未使用且未过期的预约；取消后状态为 `cancelled` 并立即解除占用。
- 到达 `expiresAt` 且未开始充电的预约变为 `expired` 并解除占用。
- 冻结用户时，其有效预约变为 `cancelled`。
- 电站停用或电桩变为故障、离线时，相关有效预约变为 `expired`。

过期采用惰性处理。所有涉及电站、电桩或预约的读写操作在读取业务状态前，必须在事务中回收相关过期预约。查询结果不得把已经到期的预约显示为 `active`，也不得把对应电桩显示为 `reserved`。

服务每次启动时，在一个事务中把已到期的活跃预约标为 `expired`，把其余活跃预约标为 `cancelled`，并解除全部相应电桩占用。事务失败时服务启动失败。

## 9. 模拟充电与订单

### 9.1 开始充电

- 用户不得已有 `charging` 或 `awaiting_payment` 订单。
- 用户有有效预约时，只能携带该预约启动其对应电桩。
- 用户没有有效预约时，可以直接启动未软删除、active 电站中的 `available + online` 电桩。
- 开始操作在一个事务中创建 `charging` 订单、把电桩置为 `charging`，并在有预约时把预约置为 `used`。
- 订单在开始时保存电站 ID、电桩 ID、可选预约 ID、功率 W 快照、单价快照和 `startedAt`。
- 开始充电不要求钱包具有余额。

### 9.2 充电过程

- 后端假定电桩从 `startedAt` 起始终以订单中的额定功率输出。
- 经过秒数为后端当前时刻与 `startedAt` 之间的完整秒数。
- 原始电量为 `powerW * elapsedSeconds` Ws。
- 订单处于 `charging` 时，每次查询都按查询时刻动态返回经过时长、电量和 `amountFen` 当前计费，不将这些动态值固化为最终账单。
- 当前计费与最终计费使用同一公式：

```text
amountFen = roundHalfUp(powerW * elapsedSeconds * unitPriceFenPerKwh / 3,600,000)
```

- 充电只由用户主动停止，不设置电池容量、目标电量、余额门槛、最长时长或自动停止。
- 后端重启后，`charging` 订单继续按原 `startedAt` 计时，停机时间计入充电。
- 当前系统时刻早于 `startedAt` 时，查询计费或停止操作失败，不得产生负时长、电量或金额。

### 9.3 停止充电

- 停止请求不接受客户端提供的电量、时长或金额。
- 后端使用接收停止请求时的时钟计算最终完整秒数、原始电量和金额。
- 同一事务内记录 `stoppedAt`、最终秒数、原始电量和 `amountFen`，把订单置为 `awaiting_payment`，把电桩占用状态置为 `available`，并增加电桩累计充电次数和累计秒数。
- 运维状态不因停止而改变。
- 0 秒、0 Wh 和 0 分订单合法，并计为一次充电。
- 重复停止返回已经生成的订单结果，不重新计算账单，不重复更新累计值。

### 9.4 结算

- 只有订单所属用户可以结算 `awaiting_payment` 订单。
- 支付方式仅为钱包。
- 余额足够时，在同一事务中扣减余额、写入 `charge_debit` 流水、记录 `settledAt` 并把订单置为 `settled`。
- 余额不足时返回 `INSUFFICIENT_BALANCE`，不扣款，订单保持 `awaiting_payment`。
- 重复结算返回已结算订单，不重复扣款或写流水。

### 9.5 查询与累计统计

- 当前用户最多只有一个 `charging` 或 `awaiting_payment` 订单。
- 当前未完成订单查询返回该唯一订单；不存在时返回成功且数据为 `null`。
- 电桩累计充电次数在订单成功停止时增加 1。
- 电桩累计充电时长内部保存整数秒，对外累计分钟为总秒数向下取整除以 60。
- 用户订单可按状态和创建时间区间筛选。
- 管理员可额外按用户、电站和电桩筛选订单。

## 10. 管理功能与统计

### 10.1 用户管理

- 管理员可分页查询用户、查看用户详情、订单摘要和钱包流水。
- 手机号搜索使用 ASCII 子串匹配；空搜索返回全部用户。
- 管理员只能把用户状态改为 `active` 或 `frozen`。
- 重复冻结或解冻幂等成功。

### 10.2 电桩状态统计

后端返回以下原始事实，不返回百分比、在线率或合并展示状态：

- 未软删除电桩总数；
- 占用状态 `available`、`reserved`、`charging` 的各自数量；
- 运维状态 `online`、`fault`、`offline` 的各自数量。

统计可以按电站 ID 限定范围。前端根据这些计数计算在线率、百分比和展示状态。

### 10.3 营收

- 只有已结算订单计入营收，确认时点为 `settledAt`。
- 充值不计入营收，待结算订单不计入营收。
- 软删除电站或电桩后，其历史已结算订单继续计入营收。
- 营收查询不传时间范围时返回累计营收；同时传入 `from` 和 `to` 时返回该区间营收。
- 营收和趋势查询可以按电站 ID 筛选，包括已经软删除的电站。
- 趋势查询必须传入 `from`、`to` 和固定 UTC 偏移 `+HH:MM` 或 `-HH:MM`。
- 趋势按该固定偏移下的自然日分桶；首尾日期按请求区间与自然日的交集统计。
- 没有营收的日期也返回金额 0、订单数 0 的桶。
- 趋势区间长度不设上限。
- 每个桶的订单数是 `settledAt` 落入桶内的已结算订单数量，包括 0 分订单。

## 11. HTTP 契约

### 11.1 版本与响应

- 健康检查路径为 `/health`，业务接口统一位于 `/api/v1`。
- 成功响应使用 `{data, meta}`，错误响应使用 `{error: {code, message, details}, meta}`。
- 每个 HTTP 响应均在 `X-Request-Id` 响应头中返回请求 ID；JSON 响应同时在 `meta.requestId` 中返回。
- 204 响应没有正文。
- JSON 对象中的未知字段被忽略。
- 路径不存在返回 404，路径存在但方法不支持返回 405，JSON 媒体类型错误返回 415。
- 不实现请求限流，不返回 CORS 响应头。

### 11.2 请求 ID

- `X-Request-Id` 可选。
- 提供时必须是合法 UUID，并在响应中原样返回。
- 省略时由后端生成 UUID。

### 11.3 分页与排序

- `page` 从 1 开始，默认 1。
- `pageSize` 默认 20，最大 100。
- 超出最后一页时返回空列表，不返回错误。
- 电站、电桩和用户默认按 ID 升序。
- 订单、预约和钱包流水默认按创建时间降序，再按 ID 降序。

### 11.4 幂等

- 充值、创建预约、开始充电、停止充电和结算必须提供 `Idempotency-Key`。
- 幂等作用域为认证主体、HTTP 方法、请求路径和 key。
- 后端保存规范化请求体哈希、HTTP 状态和业务结果，保留期由配置决定。
- 保留期内同一作用域、同一请求体的重试返回首次业务结果，不重复执行；响应使用当前请求的 request ID。
- 保留期内同一作用域、不同请求体返回 `IDEMPOTENCY_KEY_REUSED`。

## 12. 错误处理与一致性

### 12.1 业务错误

| 条件 | 错误码 |
| --- | --- |
| 字段缺失、类型错误、范围错误、非法枚举 | `VALIDATION_ERROR` |
| 未认证 | `UNAUTHORIZED` |
| 管理员凭据错误 | `INVALID_CREDENTIALS` |
| 权限不足 | `FORBIDDEN` |
| 冻结用户执行不允许的操作 | `USER_FROZEN` |
| 资源不存在或用户访问他人资源 | `NOT_FOUND` |
| 已有未完成订单 | `ACTIVE_ORDER_EXISTS` |
| 电桩不可用 | `CHARGER_UNAVAILABLE` |
| 其他非法状态转移 | `INVALID_STATE_TRANSITION` |
| 幂等键被用于不同请求 | `IDEMPOTENCY_KEY_REUSED` |
| 余额不足 | `INSUFFICIENT_BALANCE` |
| 充值后将超过钱包余额上限 | `BALANCE_LIMIT_EXCEEDED` |
| 地址无结果 | `GEOCODE_FAILED` |
| 路线无结果 | `ROUTE_NOT_FOUND` |
| 地图供应商鉴权或响应异常 | `PROVIDER_ERROR` |
| 暂时无法访问地图或数据库忙超时 | `SERVICE_UNAVAILABLE` |
| 未预期服务错误 | `INTERNAL_ERROR` |

校验错误在 `details` 中按字段列出原因。任何失败的写操作不得留下部分业务变更。

### 12.2 事务与并发

以下操作必须分别在单个 SQLite 事务中完成：

- 创建预约与锁定电桩；
- 取消或使预约失效与解除占用；
- 开始充电；
- 停止充电、释放占用和更新电桩累计值；
- 结算、扣款和写入钱包流水；
- 冻结用户及取消其预约；
- 电站停用或电桩异常及使预约失效；
- 软删除电站及其电桩。

事务使用条件更新和数据库唯一约束处理并发竞争。SQLite 连接启用外键和 WAL，busy timeout 默认 5 秒且可配置。写锁等待超时后回滚并返回 `SERVICE_UNAVAILABLE`。

未处理异常或数据库错误必须回滚当前事务并返回 `INTERNAL_ERROR`。响应和日志不得暴露 SQL、文件路径、密码、令牌、头像正文、地图密钥或堆栈。

## 13. 启动、健康与关闭

- 首次启动事务性创建数据库结构和默认管理员。
- 后续启动根据数据库结构版本执行内置迁移，迁移失败时拒绝启动。
- 启动时校验唯一业务约束。发现同一用户存在多个未完成订单、同一电桩存在多个有效占用等矛盾时拒绝启动，不自动修复。
- 启动时恢复 `charging` 订单对应电桩的占用状态，保留数据库中的运维状态。
- `/health` 无需认证；只有服务已完成启动且 SQLite 简单查询成功时返回 200，不返回配置或敏感信息。
- 正常关闭时停止接收新请求，最多等待 1 秒使正在处理的请求完成，然后关闭数据库连接。
- 正常关闭不改变任何业务状态；下次启动按启动预约规则处理活跃预约。
- 日志至少记录启动、关闭、配置错误、迁移失败和未预期服务错误，不记录敏感信息。日志输出到标准错误，不要求轮转或集中采集。
