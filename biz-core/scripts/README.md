# 后端演示数据

`seed_demo_data.py` 使用 Python 3.8+ 标准库，在启动后端前创建新的 SQLite 数据库。
脚本从同一 checkout 的 `src/database.cpp` 读取 v1 建表语句，不需要先运行后端。
默认管理员和服务凭据仍由后端首次启动初始化。

在仓库根目录执行：

```bash
cmake -S . -B build -DCMAKE_PREFIX_PATH="$HOME/Qt/6.2.4/gcc_64" -DBUILD_TESTING=OFF
cmake --build build --target biz-core -j4
python3 biz-core/scripts/seed_demo_data.py \
  --database "$PWD/build/biz-core/data/demo.sqlite3"
EV_CHARGER_DATABASE_PATH="$PWD/build/biz-core/data/demo.sqlite3" \
  ./build/biz-core/biz-core
```

必须让后端使用生成的同一个数据库路径；后端默认的数据库文件名是
`data/ev-charger.sqlite3`，相对路径以可执行文件目录为基准。
脚本要求目标文件不存在，重复执行会报错且不修改已有数据。需要另一套数据时使用新的文件名。
可用 `--days 30` 调整历史天数（1–365），用 `--seed 42` 调整随机序列。
时间以运行时刻为基准，按 UTC 毫秒格式保存；相同种子保留相同的数据分布。

默认包含：

- 上海 8 个电站（7 个启用、1 个停用），坐标可用于地图和附近电站检索。
- 48 个电桩，覆盖快充、慢充及在线、故障、离线状态，不同功率和单价。
- 24 个用户，包含正常、冻结及零余额账户。
- 近 90 天每天 8–16 笔已结算订单，支持分页、订单筛选、今日/周/月营收展示。
- 1 笔待支付订单，以及已使用、已取消、已过期预约。
- 与订单金额、钱包余额和电桩累计次数/时长一致的充值及扣款流水。

| 账户 | 用途 |
| --- | --- |
| `13800000001` | 普通用户：历史订单、余额、预约和开始充电 |
| `13800000002` | 待支付订单，可演示结算 |
| `13800000003`–`13800000022` | 其他普通用户 |
| `13800000023` | 冻结用户 |
| `13800000024` | 冻结且零余额，可由管理员解冻后演示充值 |
| `admin` / `123456` | 首次启动时后端创建的管理员 |

普通用户按现有后端规则仅使用手机号登录。历史订单不占用当前电桩；
不预置充电中订单，避免数据库放置一段时间后累积不真实的费用。
后端启动时会取消未到期的活动预约，所以活动预约和实时充电应在前端现场创建。
历史订单可以属于当前故障、离线或停用的设备，表示设备状态后来发生了变化。

回归检查（流水金额为正、扣款匹配订单、逐笔余额及最终余额一致）：

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s biz-core/scripts -p 'test_*.py'
```

修复脚本不会修改之前生成的数据库；请使用新文件名重新生成并切换后端数据库路径。
