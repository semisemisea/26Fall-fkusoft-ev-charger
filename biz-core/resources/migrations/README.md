# 数据库迁移

SQL 随 `database.qrc` 嵌入后端；运行时不依赖源码路径或外部 SQL 文件。
`000_metadata.sql` 仅引导创建版本表，每次启动执行；`001_initial.sql`
对应现有 v1 模式，保留原有表、约束和索引。已有 v1 数据库跳过该迁移，
不会在每次启动时重建被手动删除的表或索引。

每个 SQL 段只包含一条语句，以独占一行的 `-- statement-breakpoint` 分隔。
不要在 SQL 字符串或其他语句内容中使用该独占行。段内可以正常使用分号，
不采用按分号切割的方法。迁移中不要加入事务控制语句；后端统一管理事务。

新增升级时：

1. 添加下一个连续版本的 SQL 文件，不修改已发布的迁移。
2. 在 `database.qrc` 注册资源，并追加到 `database.cpp` 的迁移列表。
3. 同步更新演示数据脚本的迁移文件列表和最终版本号。
4. 验证空库初始化、旧版本升级、重复启动和失败回滚。

后端先检查版本，再依次执行待应用迁移；DDL 和版本更新在同一事务中完成。
默认管理员的动态盐、密码哈希与时间仍由 C++ 生成，保留启动时补建行为。
演示数据脚本读取同一份 SQL，默认管理员和服务凭据留给后端首次启动创建。
